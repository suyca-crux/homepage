## Usage guidelines

- Primary actions use the `primary` color; on hover shift to `primary-600`, on active to `primary-700`.
- Cards take the `card` rounded role and a medium shadow.
- Buttons take the `button` rounded role and a small shadow on the primary variant.
- Inputs take the `input` rounded role; focus ring follows the interaction-states spec.
- Body text uses the `body` typography role.
- Section spacing: use the `3xl` spacing token between major blocks.
- Stack spacing within a block: use the `md` spacing token.

## Appended decisions (flagged per rule 3)

The following were required to implement this spec but are not derivable from the
values above. They are recorded here so the spec stays authoritative.

### Ownership

Tokens are owned by `@vipelar/ui` and declared once in `ui/src/styles/theme.css`,
exported as `@vipelar/ui/theme.css`. Consumers `@import` that file so their own
Tailwind build sees the same `@theme` — utilities are generated at build time, so
sharing values at runtime alone is not sufficient. There is no consumer-side
override mechanism: using `@vipelar/ui` means using this spec.

### Dark mode

The frontmatter carries a single ramp, so dark values are derived. There is no
theme-switching semantic layer; components pair a light utility with a `dark:`
one. Because the theme is toggled by a `.dark` class on `<html>` rather than by
OS preference, `theme.css` redefines the variant as
`@custom-variant dark (&:where(.dark, .dark *))`.

| Role            | Light         | Dark          |
| --------------- | ------------- | ------------- |
| Page background | `white`       | `neutral-950` |
| Surface / card  | `neutral-50`  | `neutral-900` |
| Muted surface   | `neutral-100` | `neutral-800` |
| Body text       | `neutral-900` | `neutral-50`  |
| Faded text      | `neutral-500` | `neutral-400` |
| Border          | `neutral-200` | `neutral-800` |
| Primary         | `primary`     | `primary-400` |

Primary shifts one step lighter in the dark theme to hold contrast.

### Alert derivations

`success` / `warning` / `danger` / `info` are single values with no tonal steps,
which is what makes alerts render identically in both themes — the intended
behaviour. Two derived sets were added because a single value cannot serve as
both fill and text:

- `--color-*-bg` — the base colour composited onto white at 15%, kept **opaque**
  so alerts stay light-on-light over a dark page. A translucent fill would take
  on the page background and break that.
- `--color-*-text` — darkened until it clears 4.5:1 on its own `-bg`
  (measured: info 5.79, warning 4.73, danger 6.29, success 5.82). The base
  colours alone reach only 2.22–3.50 and are not usable as body text.

### Typography weights

The `--text-*` roles carry size and line-height but **not** `font-weight`.
Encoding weight in the role makes it compete with `font-bold` / `font-normal` on
the same property, where the winner depends on CSS output order. The weights
specified above (headings 700, body 400) are applied at the usage site instead.

### Japanese text

`Inter` has no CJK glyphs, so Japanese falls back to `system-ui` (Hiragino Sans
on macOS, Yu Gothic UI on Windows). This is a deliberate trade-off: the site
previously used `BIZ UDPGothic`, whose universal-design legibility work is lost.
